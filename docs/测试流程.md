# 测试流程

按下列顺序验证，记录每次使用的固件 SHA256、TF 卡镜像 SHA256、板卡型号、TF 卡型号和现象。未连接板卡时只能完成软件检查，不能填写“实板通过”。

## 1. 解压 / 克隆自检

在新目录打开 PowerShell，执行：

```powershell
.\setup.cmd
.\media.cmd --help
.\media.cmd inspect .\demo\bringup.img
.\test.cmd
```

预期：离线工具初始化成功，镜像目录可读取，快速回归最后打印 `PASS: host pack/inspect, CRC rejection and requested RTL tests`。不应要求旧 `D:\hdmi\redesign`、`use` 或 `.tools` 目录。

`test.cmd` 包括格式检查、CRC 拒绝、SPI 初始化、帧页确认、未来帧调度、音频消费时间轴、暂停末样本、PCM 环形缓冲、JPEG 输入间隙和真实第五帧触发字、目录生命周期及自动重载、帧追赶与 SRAM 所有权。`test.cmd -Full` 进一步运行完整 JPEG 解码及像素对比，耗时更长。

SW0 音量控制还覆盖全部 17 档的正负 PCM 增益、静音、音量上下限、拨码消抖、按键模式隔离，以及拨回/切换媒体后的音量保持。新固件的实板步骤见 [拨码开关与音量](拨码开关与音量.md)。

HDMI 音量条测试覆盖平滑增减、静音/满幅、按帧显示/隐藏、底板外原像素保持，以及六个完整 640×480 帧通过 OSD 后的 AXI SOF/EOL 对齐。

SW1 亮度扩展测试覆盖两个模式的独立档位与保持、同时开启时 SW0 优先、模式切换时按住按键不串用，以及半亮度/全黑画面、OSD 不随画面调暗、扬声器/太阳图标、灰槽与金色填充、九个完整帧的 AXI 对齐。

SW2 对比度扩展覆盖三个模式的优先级、独立保持、按键隔离和上下限；对比度计算覆盖全部 17 档×256 组 RGB 输入、饱和裁剪、默认 8 档恒等、帧首与帧内保持；完整对比度→亮度/OSD→AXI 链路检查两帧 640×480 像素、SOF/EOL、灰槽/紫色填充与图标。实板还需确认拨回和切媒体后保持，以及亮度与对比度组合调节。

SW3 滚动文字测试覆盖图片和视频均可显示、无效媒体/切换时隐藏、开/关、移动步长与回绕、重新进入、帧内位置与颜色保持、四个完整帧的 AXI 对齐和带外像素保持；检查汉字颜色随时间循环、Latin 与逗号保持金色。顶层检查 SW3 不抢占 S0/S1。文字字模顺序、2 倍缩放与实际输出位置另有捕获图像验证。上板步骤见 [SW3 滚动文字](SW3滚动文字.md)。

真实自然图片回归可单独运行：

```powershell
# 在 PowerShell 中载入本地离线工具路径；不会写卡。
. .\tools\runtime.ps1
& $taskPython .\sim\check_frame.py .\sim\fixtures\legacy_frames.img --media 1 --frame 4 --iverilog $taskIcarus
```

该样本保留旧视频第五帧的原始压缩字节，专门覆盖曾造成宽高清零的输入停顿缺陷。

## 2. 从源码编译

```powershell
.\build.cmd -Target segtest -TdRoot 'E:\ANLU-TD'
.\build.cmd -Target hdmitest -TdRoot 'E:\ANLU-TD'
.\build.cmd -Target TFMEDIA3_Player -TdRoot 'E:\ANLU-TD'
```

预期：综合、布局布线及 bitgen 完成，SWNS/HWNS 非负、STNS/HTNS 为 0。报告和 bit 位于对应 `output/<目标>-<时间戳>/`。TD 即使在 Tcl 出错后返回 0，脚本也会检查日志和时序报告，不能只凭进程退出码判断通过。

## 3. 数码管

下载 `firmware/01_segtest.bit`，按原校准流程验证八位数码管和逐位轮亮；接线配置 4 已实测完整显示 `76543210`。测试固件中的配置切换按钮与播放器的媒体按钮功能不同，详见 [数码管测试](数码管测试.md)。

## 4. 独立 HDMI

下载 `firmware/02_hdmitest.bit`，不插 TF 卡，连接 HDMI 显示器。预期出现稳定测试图；若无信号，先检查下载、板卡时钟、管脚、HDMI 线和显示器。

## 5. 播放器与短测试镜像

用写卡工具将 `demo/bringup.img` 写入明确选定的 TF 卡，下载 `firmware/08_player_avsync.bit`，复位。预期显示彩条图片约 3 秒，播放两秒测试视频，随后循环。该镜像含静音 PCM，不用于听感验证。

按板上 S0，应切换到下一媒体；按 S1，应暂停，再按继续。无卡、无效卡和不支持的图像格式应有可观测错误，不能把 `00` 单独视为播放成功。

## 6. 自有图片与带声音视频

```powershell
.\media.cmd pack 'C:\media\a.jpg' 'C:\media\b.png' 'C:\media\clip.mp4' --audio -o .\output\av_test.img
.\media.cmd inspect .\output\av_test.img
```

顺序即播放顺序。分别验证：两张图片轮播、S0 跳转、视频超过原第五帧持续播放、后半段主观音画同步、声音结束后自动切到下一媒体、暂停/继续和末尾附近暂停。复杂素材若超出帧预算，先降低压缩质量或简化画面；提高预算可能增加视频追赶丢帧。

建议完整播放至少一段一分钟左右、口型或敲击声清晰的视频，多轮循环。记录声音领先还是落后以及大致偏差；“观看满意”与“仪器测得零偏差”分别记录。需验证无丢帧 25 fps 时，应额外测量帧显示次数与时长，不能仅依据文件参数。

## 7. 故障采集与回退

记录完整八位数码管、卡镜像、触发步骤和画面状态。发生超时时显示可能被冻结为诊断快照，位定义参见数码管文档和 `tfmedia3_top.v`。

保留当前可用固件和镜像，在另一个文件名生成新镜像、在新的输出目录构建。回退时重新下载 `firmware/08_player_avsync.bit`；无需删除失败产物。

## SW4 音频波形验收

下载含 SW4 功能的新固件后，播放带声音视频，拨下 SW4，确认左侧波形随声音变化且视频、声音继续正常播放。调低 SW0 音量，观察幅度减小；设为 0，最新格应在下一显示帧变成水平线，约 0.53 秒后整条历史应为水平线。恢复音量后波形恢复。验证 SW3 文字及底部设置条可同时显示，拨回 SW4 后面板隐藏，S0/S1 仍按设置模式执行原功能。

新增 `tb_audio_wave_overlay` 已纳入回归：检查 按帧分箱、有符号极值、历史顺序、帧内历史稳定、静音、开关、像素与 AXI 帧边界。RTL 预览不替代实板验收。
