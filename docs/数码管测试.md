# 八位数码管接线校准

下载 `firmware/01_segtest.bit`。无需 TF 卡和 HDMI。
板钟 K14=50 MHz；SCLK=T14、RCLK=R12、DIO=R14；S1=F7、S2=E7、RESET=H14，按键低有效。
本程序加入约 5.24 ms 的上电复位和 5 ms 按键消抖，每次按键只推进一次。

默认模式同时显示逻辑位 0..7。先记录从左到右显示内容。
S1 每按一次将配置加 1（0..15，循环）；RESET 将配置与模式复位。

| 配置位 | 0 | 1 |
|---|---|---|
| bit0 | 高电平位选 | 低电平位选 |
| bit1 | 低电平段码 | 高电平段码 |
| bit2 | 先位选字节，后段码字节 | 先段码字节，后位选字节 |
| bit3 | 段字节按原位序 | 段字节反转 |

配置值就是复位后 S1 的累计次数对 16 取余。
若显示 `76543210` 或其他 0..7 排列，电平与段码已基本匹配，剩下是物理位序映射。
请反馈该排列及按了几次 S1。顶层 `SEG_CONFIG` 参数可固化对应配置。

S2 循环切换：

1. 同时显示 0..7。
2. 每秒仅选一个逻辑位，显示与逻辑位编号相同的数字。可记录亮位移动顺序。
3. 所有位每秒只亮一个段，共 8 步，包含小数点。记录亮段顺序可确定任意段线置换。

第三种模式的逻辑顺序是段位 bit0..bit7，默认编码假设 a,b,c,d,e,f,g,dp。
若 16 种组合都无法读出数字，第三种模式比继续猜测更有效。
595 的两个字节均 MSB 先发，最后一个移位上升沿和锁存上升沿间隔 0.5 µs。
三线接口不能直接推断底板三极管的有效电平。

## 本次上板反馈

用户反馈：复位后按板上 S0 四次完整显示“76543210”，再按板上 S1 可逐位轮亮。
因此播放器默认采用 `SEG_CONFIG=4`：先发段码字节，再发位选字节；段码低有效，位选高有效，段字节不反转。
八位均可读，物理从左到右对应逻辑位 7..0，因此播放器现有高位到低位排列无需反转。
原始校准 bit 保持从配置 0 开始，仍需按四次选择键，方便重复相同实验。

板上丝印与 HDL 信号名不同：板上 S0 对应文中/HDL 的 S1（F7），板上 S1 对应 S2（E7）。
在播放器中，板上 S0 请求下一媒体，板上 S1 暂停/继续。
播放器从左到右为 `EE D F P T I S`：两位错误码、解码状态、帧号低位、暂停标志、媒体类型、媒体索引、播放状态。

## 解码超时定位版

用户在主播放器中报告 `34F0010r`、HDMI 有信号但一直黑屏。旧版发生超时后把解码阶段改成 F，无法据此确定具体等待点。
以下为历史定位记录，`04_player_diag.bit` 留在原工程中，不随当前包分发。当前 `firmware/08_player_avsync.bit` 保留超时快照：错误 34 时八位改为 `34 S F WWWW`，所有数字均为十六进制：

- S：超时前解码阶段；1 等 SDRAM 写请求应答，2/4 发 SRAM 请求，3/5 等 SRAM 数据，6 等 JPEG 接收输入，7 等 JPEG/像素完成，8 等 SDRAM 写完成。
- F：bit3 全帧像素已送出，bit2 JPEG 核 idle，bit1 全部 JPEG 输入已交接，bit0 曾收到 SDRAM 写完成。
- WWWW：当前 32 位 JPEG 字的零基序号；最后一个字已交接后仍保留其序号，不是成功接收字数。

例如 `34100000` 表示尚未获得 SDRAM 写请求应答；`3472xxxx` 表示输入已交接，但还未完成全帧像素输出且 JPEG 未 idle。
复位后重新执行一次，反馈最终完整八位即可。此版本增加定位信息，并未据旧版的 F 状态直接判定硬件故障点。

第二轮实板读数 `34722022`：停在阶段 7，标志 2 表示 JPEG 输入已交接、核未 idle、整帧像素未完成、SDRAM 未完成；最后输入字序号 0x2022。
发现解析器存在末字提前结束问题，修复版保留上述冻结显示格式。
视频首帧实板错误 `347209E1` 对应末字序号 0x09E1，和 CES 视频首帧 10,119 字节一致；修复后该帧 RTL 完整解码。
用户确认旧版仅 logo 正常，该参考 JPEG 末字只有一个有效字节，避开原缺陷。
两张图片切换失败还会受解码错误态永久 busy 影响；修复版在按键请求换媒体时清除失败的解码器，并在各独立 JPEG 开始前清理核状态。
