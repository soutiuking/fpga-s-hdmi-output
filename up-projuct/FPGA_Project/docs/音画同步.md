# 音画同步修订（08）

07 用户已实板确认视频可以连续播放，声音与画面切换流畅；长时间播放后声音领先画面。
旧调度中，音频按 PCM 请求持续消费，视频始终逐帧递增。超过预算的读卡/解码会使视频永久落后；
40 ms 定时脉冲和单比特待显示标志不能表示落后了多少帧。

08 使用同一条媒体时间轴：

| 环节 | 行为 |
|---|---|
| 起点 | 第一帧通过场边界及 SDRAM 读页确认后，开启音频和时间轴 |
| 有音轨视频 | 实际消费 1,920 个 PCM 样本推进一帧，48,000 / 25，无独立视频时钟累积误差 |
| 无音轨视频 | 40 MHz / 25 的计数器推进，保持 25 fps 目标 |
| 提前完成的 JPEG | 连同原始帧号保留，到时间轴抵达该帧才提交显示 |
| 预读 | 直接索引下一帧；若已落后，则预读时间轴之后一帧 |
| 严重落后的压缩缓存 | 超过一帧时，复用尚未提交的 SRAM 槽读取当前时间轴附近的帧 |
| 暂停/音频缺数 | 暂停时冻结显示提交和新 PCM 消费；已在途的至多一个样本仍计数，防止末样本丢计数；缺数不推进时间 |
| 结束 | 等音轨对应完整时长以及最后视频帧完成显示，再切换媒体；正常 PCM EOF 输出静音，不报欠载 |

跳过过期视频帧用于避免落后不断累积，不改变文件中的 640×480 / 25 fps 参数。
卡和解码吞吐不足时，实际显示帧数可能少于 25 帧/秒，不能据此宣称已经达到连续无丢帧 25 fps。
音频数据保持原顺序，追赶不丢 PCM。HDMI 提交仍量化到约 59.52 Hz 的场边界。
固定的读卡/解码延迟、输出设备自身延迟仍需实板测量，样本时间轴验证不能替代主观或仪器音画同步测试。

代码在 `tfmedia3_reader_frontend.v` 内的 `tfmedia3_playback_clock`、`tfmedia3_top.v` 和 `pcm_audio_buffer.v`。
格式和卡内容未变，可以继续使用现有卡；07 下载文件保留在原工程，本独立包仅分发 08 验收版及两个板级测试固件。

验证包括：

- `tb_playback_clock.v`：1,393 帧/55.72 秒的样本计数，无累积帧数偏差，暂停、PCM 停顿和静音视频末帧时长。
- `tb_pcm_playhead.v`：PCM 环形缓存回绕、样本顺序、准确消费数量、暂停和 EOF 不误报欠载。
- `check_top_recovery.py`：真实顶层将未来帧保留到播放时间，暂停不换页，媒体切换不泄漏旧待显示页。
- `tb_reader_catchup.v`：模拟解码落后，真实目录/帧表/DMA/SRAM 路径直接从过期帧 1 查到帧 9，并保留末帧及 SRAM 所有权。
- `tb_reader_lifecycle.v`：带音频 SD 竞争的六帧播放、暂停和自动媒体重载。

原验收合并结果在本包 `docs/evidence/avsync_final_quick.log`，独立样本时钟及暂停末样本检查在 `docs/evidence/avsync_clock.log`。2026-10-15，用户实板测试 08 后反馈“我很满意”，08 已记为当前验收版本；尚未进行音画偏差的定量标定。
原工程 `sim/avsync_quick.log` 是早期测试记录，其中追赶用例错误地要求丢弃仅落后一帧的缓存，等待条件导致未结束；该用例已改为符合“一帧容差”的预期。该早期日志留在原目录，不随独立包分发。
