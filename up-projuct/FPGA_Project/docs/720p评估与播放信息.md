# 原生 720p 评估与播放信息显示

评估日期：2026-10-19。目标为原生 1280×720；本次没有将 640×480 放大后标为画质提升，当前媒体和 HDMI 仍为 640×480。

## 原生 720p 的限制

现有架构不能直接扩到 1280×720、25 fps 并保留全部功能。此结论来自现有 RTL、10 版布局布线报告和带宽计算，不是已经实现并完成布局布线的 720p 实测结果。

| 项目 | 当前 640×480 | 原生 1280×720 的影响 |
|---|---|---|
| 每帧像素 | 307,200 | 921,600，增加到 3 倍 |
| JPEG MCU 行缓存 | 640×16×24 bit，9 块 BRAM32K | 1280×16×24 bit，按现有 4096×8 分银行方式需 15 块 BRAM32K |
| 全工程 BRAM32K | 16 / 16 | 其余模块保留时需 22 / 16，超出 6 块 |
| DSP | 29 / 29 | 无余量追加硬件乘法滤镜；扩大分辨率本身不必增加 DSP |
| SDRAM 双显示页 | 614,400 个 32 bit 字 | 1,843,200 个字，仍在 21 bit 地址空间内；容量不是首要瓶颈 |
| 解码与行缓存输出 | 40 MHz，填满条带后再逐像素排空 | 两阶段至少 1,843,200 拍，即 46.08 ms/帧；未计 JPEG 内部等待和输入时间，已经超过 25 fps 的 40 ms 预算 |
| 60 Hz HDMI 读带宽 | 73.728 MB/s，渐变时约翻倍 | 单页 221.184 MB/s；图片渐变同时读两页需 442.368 MB/s |
| HDMI 时钟 | 像素 25 MHz，串行 125 MHz | 标准 720p60 像素 74.25 MHz，串行 371.25 MHz，需重配 PLL 并重新验证 PHY、FIFO、OSD 和时序 |

SDRAM 接口理论上限为 125 MHz×32 bit，即 500 MB/s。720p60 图片交叉渐变的读数据已经占理论上限约 88.5%，还未计刷新、仲裁和突发间隙。视频直接显示加 25 fps 写入的数据量为 313.344 MB/s，需实际验证有效带宽；图片渐变只用于图片，不能把视频连续写带宽与图片混色读带宽当作必然同时发生。

剩余的 24 块 BRAM9K 不是完全无用：可保留三个 4096×24 的 BRAM32K 银行，再以 24 块 BRAM9K 补足另外两个银行，实现 1280×16 缓存。但这会用满全部 64 块 BRAM9K，并且不会解决填充/排空串行执行的吞吐限制。因此“剩余 LUT 足够”不能证明原生 720p25 可行。

还需要修改 JPEG 像素横坐标位宽、条带地址和计数器、45 个条带结束条件、尺寸校验、帧页地址/长度、HDMI 时序及 VIC、AXI 每行末像素判断、所有 OSD 坐标、制卡工具和卡头尺寸校验。现有每个 JPEG 的 64 KiB 压缩槽也要重新评估，不能保证提高分辨率后仍能保持当前压缩质量。现有卡不可直接作为原生 720p 素材。

推荐的后续改造是先把条带缓存改成可并行填充/排空的结构，或让 JPEG 直接写入 SDRAM，并评估 RGB565、减少图片混色读流量、重分配 BRAM 和更大压缩槽。也可单独开发较低帧率的原生 720p 图片/视频版本；这些均需重新综合、时序和实板验收。本次交付保留可验证的 480p 链路。

## 剩余开关的实现

| 开关 | 功能 | 位置及格式 |
|---|---|---|
| SW5（P14） | 播放进度条 | x=64..575、y=404..411，青色填充、灰色底槽 |
| SW6（P16） | 媒体序号 | 右下方 `01/20`，从 1 开始，分母为目录中的全部图片和视频数 |
| SW7（P15） | 播放时间 | 右下方 `00:01/00:03`，已播放时间 / 总时长，格式为分:秒 |

均为 ON/接地/低电平启用，OFF 隐藏；互相独立，不占 S0/S1，可与 SW0～SW4 同时开启。显示位于原有设置条上方，避开左下角暂停标志。RESET 后按开关实际位置重新采纳。

视频复用 `playback_frame_number`，有音频时跟随实际 PCM 消费时间轴，静音视频沿用已有定时；不使用预读/解码帧号。图片复用既有三秒轮播计时器，暂停时冻结。媒体加载/切换或元数据无效时隐藏信息，重新取得有效数据后更新；时间取整秒，超过 99:59 时保持 99:59，进度仍按完整长度计算。这里显示播放进度，不提供拖动或按键快进功能。

`playback_info_overlay.v` 在读卡域用一个共享的逐位除法器计算比例、分秒和十进制数字；没有新增 DSP、BRAM 或 PLL。进度量化为 512 个像素位置；接近结尾时最后一档按满条显示。整组结果使用请求/确认翻转握手跨入视频域，源端保持数据到确认返回，视频域在每帧首像素统一采纳。RGB、DE、VS 一起延迟一拍。

## 验证及上板

专项回归 `sim/tb_playback_info_overlay.v` 覆盖独立开关与全部启用、数字像素、AXI 像素总数/行末/帧首对齐、图片和视频时间、暂停保持、重新开始/结束/越界、长视频乘积溢出、无效元数据及异步时钟传输。常规 `test.cmd` 自动执行，完整 JPEG 解码验证使用 `test.cmd -Full`。

11 版最终资源为 LUT 16501/19600、寄存器 10451/19600、BRAM9K 40/64、BRAM32K 16/16、DSP 29/29、PLL 3/4。仍剩 3099 LUT、9149 寄存器、24 BRAM9K 和 1 PLL。最终 SWNS=1.056 ns、HWNS=0.021 ns、STNS/HTNS=0。固件、资源和时序结果见 [固件说明](../firmware/README.md)。实板需检查 SW5～SW7 的 ON 方向、图片暂停/恢复、视频含音轨与无音轨、手动切换和自动循环、全部 OSD 同时显示及长时间运行。仿真和布局布线通过不替代实板验收。
