## 修复内容

- SD：原控制器在 ACMD41 完成即发布 init_done，此时仍在发 CMD16，目录首次请求可能丢失。改为进入可接受扇区请求状态后发布。
- 上电：加入约 5.24 ms 上电复位，各工作域同步释放，避免必须按一次复位才能启动。
- 帧页：压缩帧缓存槽和显示帧页独立。显示域只在新场读请求前换页，等 SDRAM 读请求确认后才释放旧页。
- 调度：预读下一压缩帧时保留当前解码/显示所有权；末帧实际提交后才进入停留/换片，避免末帧被媒体切换清除。
- 暂停：保持待显示帧和已显示页，恢复后继续。
- 输入检查：帧范围、帧率、SD 初始化超时、解码/写完成超时使用独立错误码。
- 资源：目录只缓存当前条目；切换时重读一个目录扇区，保持旧卡布局和 20 项容量。
- 数码管：提供三线串行的 16 种接线组合和逐位/逐段模式。

## 帧率与音频限制

设计使用 25 fps 时间轴；HDMI 像素钟是参考 PLL 的 25 MHz，实际 640×480 刷新约 59.52 Hz。
帧切换因此量化到 HDMI 场边界，25 fps 素材会以 2/3 场交替显示。
SPI 数据间隔和卡延迟限制吞吐，单帧 64 KiB 只是缓存上限。脚本视频默认预算 28000 字节，仍需按卡实测。
超期时保持上一完整帧，无未完成帧显示；08 会跳过过期视频缓存以追赶统一时间轴，不保证任意素材、任意卡都无丢帧达到 25 fps。
沿用 48 kHz PCM 音轨通路，未完成实板音画同步标定。音频 PLL 实际约 12.295 MHz，音频采样约 48.029 kHz。
脚本默认无音轨，以图片/视频出图为首要目标；`--audio` 可保留/补齐 PCM，测试镜像为静音。
