# AC601 / AC201 TF–JPEG–HDMI 重新设计

## 目标与边界

按用户选择保留 640×480、25 fps JPEG 视频；HDMI 输出 640×480、约 60 Hz。
电脑负责转码、排布连续扇区，FPGA 负责 SPI 读卡、JPEG 解码、帧缓冲和显示。
参考文件仅作为硬件/格式资料，其中旧报告所称“通过”不作为本次上板证据。
原 `use` 和厂家 `lab_ex5_i2s` 保留；本目录是可独立构建的修订工程。

## 自定义文件系统

兼容旧工具的 TFMEDIA3，不引入 FAT、簇链、长文件名或通用文件打开逻辑。
512 字节扇区，LBA 0 超级块（CRC32），LBA 1 顺序目录（最多 20 项）。
FPGA 只缓存当前条目，切换媒体时重读一个目录扇区，避免把整张目录做成寄存器阵列。
每个媒体包含一个元数据扇区（CRC32）、连续的 `<offset,size>` 帧表、连续 JPEG 区和可选 PCM 区。
图片一个 JPEG 帧，停留 3 秒；视频固定 25 fps。整数 little-endian。
完整字段见 `docs/TFMEDIA3_FORMAT.md`。`tools/media_card.py` 负责生成、检查及写入镜像。
裸卡写入会覆盖分区；只生成镜像不需要连接 TF 卡。

## 硬件通路

50 MHz 板钟 K14 → PLL → 40 MHz 读卡/JPEG、125 MHz SDRAM、25/125 MHz HDMI。
TF SPI → 单扇区仲裁 → 目录/帧表 → DMA → 板载 SRAM 两个 64 KiB 压缩帧槽。
JPEG 核支持 baseline、8 bit、YCbCr 4:2:0，逐帧独立解码。06 版本使用标准 Huffman 固定表，脚本强制 `optimize=False` 并检查所有表和扫描选择，不支持自定义 Huffman 表或 restart interval。
MCU 输出通过 640×16 行缓存转为光栅顺序 → 片内硬 SDRAM 两个 RGB888 帧页。
只有完整写入的帧可提交；显示域在场消隐期间接收提交，确认读页切换后才释放旧页。
压缩帧缓存编号和解压显示页编号独立分配，防止切换媒体时写入正在显示的页。
加入上电复位、各时钟域同步释放、解码超时和可观测状态。
08 增加音频主时间轴：第一帧显示确认后开启 PCM，实际消费 1,920 个样本推进一帧；提前解码的帧等待对应时间，落后过多的压缩帧直接跳到当前播放进度附近，避免持续积累音画偏差。无音轨使用 40 MHz/25 计时，详见 `docs/音画同步.md`。

## 25 fps 的实际约束

25 fps 每帧只有 40 ms。40 MHz 的原 SPI 模块最高 SCLK 约 10 MHz，命令和字节间隙会降低实际吞吐。
64 KiB 是单帧容量上限，不是 25 fps 带宽保证。脚本应限制视频帧大小并降低 JPEG 质量以适配读卡带宽。
复杂画面还受 JPEG 核运算时间限制，必须通过仿真计时和上板测量验证。
赶不上时保持上一完整帧，并跳过已过期帧追赶时间轴；不能显示未完成帧，也不能宣称任意素材都能无丢帧达到 25 fps。

## 硬件核对

管脚以用户 XLSX 表为准：CLK K14；TF CLK/MOSI/MISO/CS M2/L3/K6/R2；
HDMI CLK/D0/D1/D2 B10/D11/C11/F10；串行数码管 SCLK/RCLK/DIO T14/R12/R14；
HDL 按键 S1/S2/RESET F7/E7/H14；用户实板丝印前两个分别为 S0/S1。原理图第 3 页确认 SRAM 是 IS61WV51216、512K×16。
给定 PDF 是核心板图，不能据此推断底板数码管段序、位序及三极管有效电平。
HDMI DDC 未在给定管脚表中列出，沿用固定 VGA 时序；实际显示器兼容性需要上板验证。

## 调试顺序

1. 下载独立 `segtest.bit`，不需要插卡或接 HDMI；记录八位从左到右实际显示。
2. 板上 S0 切换配置、S1 切换显示模式；用户已验证复位后切换四次完整显示 `76543210`，播放器已固化配置 4。
3. 下载带彩条测试的工程验证 HDMI，再验证 SD 初始化、目录和 SRAM。
4. 用脚本生成已知彩色图片及短视频镜像；先检查镜像，再由用户选择目标盘写卡。
5. 完成 JPEG 全帧与场同步交接验证，再测视频帧率。

软件仿真、综合及布局布线的结果另见 `验证结果.md`；实际接线与上板显示必须由用户反馈确认。
